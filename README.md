# 중구 자전거도로 연결 상태 조사와 사고다발지점 근접성 분석

서울 11개 구 자료로 자전거도로 끝점과 사고다발지점의 공간적 근접성을 사전 분석하고, 중구 일부 노선의 연결 상태를 로드뷰로 조사한 프로젝트입니다.

**자동 분석 코드의 범위는 11개 구이며, 로드뷰 상세 조사 범위는 중구 일부 노선입니다.** 중구만을 대상으로 실행하는 별도 분석 코드는 현재 포함하지 않습니다. CSV의 시점·종점을 실제 시설 단절로 간주하지 않으며, 단절과 사고의 인과관계를 입증하는 분석이 아닙니다.

## 수행한 작업

1. 자전거도로 CSV의 시점·종점 좌표 누락과 품질 검토
2. 2024년 기준 사고다발지점 XLS와 공식 좌표 JSON의 지점명·발생건수·사망자수 대조
3. 도로 끝점과 사고다발지점 중심 사이의 50·100·150m 근접성 계산
4. 끝점 간 근접성을 이용한 연결 검토 후보 목록 생성
5. 중구 일부 노선에서 시설 연결·횡단 연결·연결 방향 안내 상태를 로드뷰로 조사

중구 로드뷰 기록은 수동 조사 결과입니다. Python 코드는 로드뷰 판정을 자동으로 생성하거나 중구 조사표와 사고자료의 통계적 연관성을 검정하지 않습니다.

## 파일 구성

| 파일·폴더 | 내용 |
|---|---|
| `analyze_2024.py` | 공식 사고다발지점 자료 대조, 끝점과 중심점 사이 거리 분석, 지도와 결과 생성 |
| `run_all.py`, `analyze.py` | 입력 자료 정리와 도로 끝점 품질·연결 후보 검토 |

| `inputs/` | 실행에 사용하는 원본 입력 자료. 공개 저장소에는 이용조건 확인 후 포함 |
| `inputs_sha256.json` | 분석에 사용한 입력 파일의 해시 기록 |
| `results/` | 11개 구 사전 분석 결과 |
| `중구_로드뷰조사_통합.csv` | 중구 조사 기록과 추가 조사자료를 통합한 표 |
| `REPORT.md` | 사전 분석 결과와 상세한 방법·한계 |

## 입력 자료와 출처

- 서울 11개 구 자전거도로 CSV 11개: 제공된 원본 파일의 시점·종점 좌표 및 기준일 사용
- TMACS 자전거 사고다발지점 XLS 11개와 `stdYear=2024`인 공식 `loadPosList.do` 응답 JSON 11개
- 서울시 교차로·횡단보도 시설·위치정보 XLSX 1개: 원본 좌표를 정리했으나 좌표계가 확인되지 않아 거리 분석에는 사용하지 않음
- 중구 로드뷰 조사: 조사자가 확인한 카카오맵 영상·서울시 지도 화면·관찰 설명을 기록

## 실행 방법

Python 3.12 환경에서 필요한 패키지를 설치하고, 이 README가 있는 폴더에서 실행합니다.

```bash
python -m pip install -r requirements.txt
python analyze_2024.py --input inputs --out results
```

`analyze_2024.py`, `run_all.py`, `analyze.py`는 같은 폴더에 두어야 합니다. `inputs`에는 분석 당시 사용한 34개 파일(CSV 11개, XLS 11개, XLSX 1개, JSON 11개)이 필요합니다. 원본 자료를 저장소에 포함하지 않았다면 별도로 준비해야 하며, 코드만으로 해당 자료를 자동 수집하지 않습니다.

이 실행 명령은 11개 구 사전 분석을 수행합니다. 기존 파일명과 자료 규모를 전제로 한 검증이 있어 다른 연도·일부 구 자료만 넣어 그대로 실행하는 용도로 일반화되어 있지 않습니다.

지도 이미지에는 `C:/Windows/Fonts/malgun.ttf`를 사용합니다. 다른 운영체제이거나 해당 글꼴이 없으면 코드의 글꼴 경로를 수정해야 합니다. 실행 시 지정한 결과 폴더의 파일이 생성·갱신됩니다.

## 중구 조사표를 읽는 방법

`중구_로드뷰조사_통합.csv`는 전체 40개 끝점 행을 유지하며, 26행에 조사 또는 참고 기록이 있습니다. **26행 모두가 독립적으로 검증된 끝점은 아닙니다.**

- 정동길 남측과 덕수궁길 일부는 공통 구간 관찰과 공식 지도 정보를 참고하여 작성했습니다. 해당 좌표의 개별 검증과 구분해야 합니다.
- 시설 연결 여부, 교차로 횡단 연결, 방향 안내 유무를 별도로 봅니다. 안내가 부족하다는 사실만으로 시설 단절로 집계하지 않습니다.
- 추가 조사자료의 분류는 `최종 분류_추가자료` 열에 원문대로 보존했습니다. 이 열은 모든 행에 공통 적용된 최종 확정 판정이 아닙니다.
- 세종대로 동측 기점·종점은 두 자료의 판단이 달라 `병합상태`에 확인 필요를 표시했습니다. 추가자료를 본문에 반영하고 이전 기록은 `기존관찰기록_병합전` 열에 보존했습니다.
- 동일 좌표의 기점·종점이나 같은 구간에 대한 참고 기록은 독립적인 여러 단절 사례로 중복 집계하지 않아야 합니다.
- 캡처 파일명은 증거 식별자입니다. 해당 이미지 파일이 저장소에 함께 포함되어 있다는 뜻은 아닙니다.

확정 통계에 사용하기 전에 판단 차이, 좌표 대응, 참고 기록과 직접 관찰 여부를 검토해야 합니다.

## 해석상의 한계

- 2024년 기준 사고다발지점 자료의 사고 집계기간은 2022~2024년입니다. 개별 사고 좌표가 아닌 반경 50m 집계지역의 대표 중심점을 사용합니다.
- 중심점이 끝점에서 100m 이내라는 결과는 개별 사고 모두가 끝점 100m 이내에서 발생했다는 뜻이 아닙니다.
- 도로 CSV 기준일은 2025~2026년이며, 로드뷰도 주로 2026년 영상입니다. 사고 당시의 시설 상태를 입증하지 않습니다.
- 도로 끝점은 행정상 노선 구분일 수 있습니다. 끝점 간 근접성만으로 실제 연결·단절을 확정할 수 없습니다.
- 좌표가 없는 구와 끝점이 있어 전체 자전거도로를 대표하지 않습니다. 구별 근접 비율을 위험 순위로 해석하지 않습니다.
- `strict`는 분석자가 정한 좌표 검토 규칙을 적용한 모드이며, 측량 검증을 통과했다는 뜻이 아닙니다. 제외 전 `reported` 결과도 함께 제공합니다.
- 실제 도로 선형, 통행 방향, 입체 교차, 이용량 등은 충분히 반영되지 않았습니다.
- 본 프로젝트는 공간적 근접성과 개선 검토 후보를 탐색합니다. 단절에 따른 사고 증가, 사고 원인 또는 개선 효과를 입증하지 않습니다.

## 검증과 AI 활용

분석 코드는 공식 좌표 자료와 XLS 대조, 고유 ID, 좌표 범위, 두 구면거리 공식의 비교, 반경별 누적 관계 및 대응 쌍 수 등을 검사합니다. 이는 계산 구현 검증이며 원본 위치 정확도나 로드뷰 판정의 정확성을 보장하지 않습니다. 실행 결과는 `results/verification.json`에서 확인할 수 있습니다.

ChatGPT·Codex를 분석 코드 작성, 자료 정리·대조, 검증 보조, 조사표 통합 및 문서 작성에 활용했습니다. 로드뷰 관찰은 조사자가 수행했고, 제공된 화면과 설명을 바탕으로 기록했습니다. AI가 모든 지점을 독립적으로 현장 확인한 것은 아닙니다.
